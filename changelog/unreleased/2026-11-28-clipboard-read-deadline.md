- **Linux clipboard reads give up on a stalled provider.** Every Wayland pipe the clipboard worker reads for one call (a paste, `plain::read_text`, a rich read, the secret watcher's check) now shares a 5 s deadline, draining included, and no further pipe is opened once it passes. A provider that starts a transfer and stops sending makes that read fail (`plain::Outcome::HostFailure`, its partial text dropped) instead of holding the worker, so later reads and writes run in order as before.
