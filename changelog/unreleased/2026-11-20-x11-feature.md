- **X11 is the default-on `x11` feature.** It carries winit's X11 backend, Rune's own X11 connections and arboard's X11 clipboard. A Linux or BSD build without it (`default-features = false`) links no X11 crate and runs on Wayland alone: without `WAYLAND_DISPLAY` or `WAYLAND_SOCKET`, `try_run` returns `event loop: no Wayland display (WAYLAND_DISPLAY and WAYLAND_SOCKET are unset); this build of Rune has no X11 support` (`run` prints it and exits 1). Such a build loses X11 and Xwayland-only sessions; the clipboard on a compositor without data-control (reads unsupported, writes fail, no X11 fallback); overlays on a compositor without layer shell (no Xwayland fallback); the screen pointer for file drops, overlays and placement; X11 global shortcuts; and X11 display ids. On Linux its clipboard is a new Wayland data-control backend with arboard's forms (text family, `text/html`, `image/png`, `text/uri-list`, the KDE secret hint, primary), rich reads capped while read; a BSD build without `x11` has no clipboard. `rune-kit`, `rune-mermaid`, `rune-knobs` and `rune-luau` depend on `rune` with default features off and leave `x11` to the app.
